# Как не упираться в лимит Claude Code — 5 правил для CLAUDE.md

Эти правила стоят у меня в Claude Code. Каждое появилось после конкретного дорогого случая из моего журнала расхода токенов. Скопируй блок ниже в свой `CLAUDE.md` (глобальный `~/.claude/CLAUDE.md` или в корне проекта) — агент начнёт работать экономнее.

## Блок для CLAUDE.md

```markdown
## Экономия лимита

1. Сначала поиск, потом чтение. Если нужна одна функция, один блок или проверка формата — сначала `grep -n` по ключевым словам. Файл целиком читать только когда нужна связная логика или файл маленький (до ~200 строк). Большой вывод команды — сразу фильтровать (`| head -60`, `jq`), не печатать целиком.

2. Одно окно — одна большая задача. Закончил тяжёлую задачу (отчёт, большой рефакторинг, серию правок) — не тянуть следующую крупную в том же окне. Предложить короткий промт-передачу для нового окна: цель, ссылки на файлы, что уже сделано.

3. Проверяющий агент — на модели попроще. Агенту-критику или ревьюеру всегда задавать дешёвую модель, потолок вызовов (до ~40), не больше 4 картинок (ужатых до 1200 px), ответ до 30 строк. Файлы больше 300 строк — только поиском.

4. Не загружать справочник ради одного факта. Нужен один факт из большой инструкции или скилла — сначала найти строку поиском. Инструкцию целиком открывать, только когда её реально выполняешь.

5. Повторилась ошибка — ставь барьер. Каждый дорогой случай записывать в журнал (дата, что случилось, сколько стоило). Первый раз — заметка. Второй — правило с примером. Третий — хук или скрипт, который механически не даёт повторить.
```

## Откуда цифры

- Файл на 1 897 строк: агент прочитал его целиком — около 25 тыс. токенов, пригодилось меньше тысячи. Поиск по ключевым словам дал бы 27 строк.
- Одно ревью на дорогой модели: 182 тыс. токенов за 29 вызовов. После правила 3 критик работает на дешёвой модели с потолком.
- Справочник на ~15 тыс. токенов был загружен ради одной цены модели.

Это мои замеры на моих задачах. У тебя цифры будут другими, но принцип тот же.
